# Замер публичных страниц: скорость, SEO, доступность

Чем мерить страницу нашего проекта и на какие грабли уже наступили. Знание про машину
и организацию, а не про конкретный репозиторий: инструменты и ключи одни на все проекты.

Все проверки — **по живому адресу**, а не по файлу на диске: половина замеров смотрит на
заголовки ответа, сжатие и кэш, которых у файла нет.

## Lighthouse — только через PageSpeed Insights API

**Локальный Chrome, Chromium, Puppeteer и `npx lighthouse` ставить и запускать нельзя.**
На cmit-prod живут чужие контейнеры, и локальный браузер вызывает OOM, который роняет
соседние сервисы. Это общее правило, не пожелание.

Вместо них — PSI API. Ключ лежит вне репозитория, `~/.config/cmit/psi-key`, `chmod 600`;
без ключа с общего IP выбивается «Quota exceeded».

```bash
curl -sS "https://www.googleapis.com/pagespeedonline/v5/runPagespeed\
?url=<адрес, urlencoded>&strategy=mobile\
&category=performance&category=accessibility&category=best-practices&category=seo\
&key=$(cat ~/.config/cmit/psi-key)"
```

**Грабля: PSI отдаёт кэшированный замер.** Прогоны подряд могут вернуть один и тот же
результат — у ответов совпадает `fetchTime`. Медианы из трёх таких «прогонов» не выходит.
Сверять `fetchTime` у каждого ответа, при совпадении повторять позже. Кэш держится недолго
и непредсказуемо: наблюдали и три одинаковых ответа подряд, и два разных с разрывом
16 секунд. Изредка PSI отвечает `500 Lighthouse returned error` — лечится повтором.

## Разметка — W3C Nu

```bash
curl -sS -H "Content-Type: text/html; charset=utf-8" --data-binary @page.html \
  "https://validator.w3.org/nu/?out=json"
```

Проходной результат — ноль сообщений типа `error` (`info` и `warning` читать, но они не гейт).

## Респонсив, клавиатура, живые проверки — MCP `playwright`

Браузер гоняется на отдельной машине (tst.cmit.ru) через MCP-сервер `playwright`, не локально.

Переполнение по горизонтали ловить сравнением `scrollWidth` с `clientWidth` на ширинах
320 / 768 / 1280 / 1920 — это надёжнее разглядывания скриншотов.

**Грабля раннера:** тест может упасть с `ENOENT ... recording2.network` уже после того, как
все проверки прошли, — это сбой записи трассы, а не страницы; повтор проходит.

**Грабля ожиданий:** `waitForLoadState('networkidle')` ненадёжен на страницах со счётчиками
и вебвизором — веб-сокет и периодические запросы не дают тишины в 500 мс, и ожидание висит
до таймаута. Ждать `domcontentloaded` и конкретный элемент, а не тишину в сети.

## Контраст

Считать формулой WCAG по парам цветов из палитры, а не смотреть глазами и не полагаться
на общую оценку accessibility: PSI проверяет только то, что видит в отрендеренном DOM.
