# ТЗ — согласованные задания

Одна задача — один файл. Порядок работы над ТЗ — скилл `/spec`.

## Конвенция

- Имя: `YYYY-MM-DD-<slug>.md`, `slug` латиницей в kebab-case.
- Дату брать из системных часов (`date +%Y-%m-%d`), а не по памяти:
  у агента внутри сессии часов нет, и «на глаз» имена уезжают вперёд накопительно.
  Часы машины идут по UTC — это и есть время проекта.
- Не вести ручную сквозную нумерацию: она конфликтует при параллельной работе агентов.
- Шаблон: `agent_docs/templates/spec.md`.
- Согласованное ТЗ задним числом не переписывать: расхождения — в раздел «Отклонения при реализации».
- Не обновлять этот README при каждом новом ТЗ.

## Статусы

Статус стоит в шапке файла и меняется по ходу работы.

| статус | что означает |
|---|---|
| черновик | идут вопросы и прототип; код не начат |
| согласовано | человек подтвердил; можно писать код |
| реализовано | код и тесты готовы, критерии приёмки покрыты |
| отменено | задача снята; в файле — строка, почему |

## Куда ссылаться

- Из `agent_docs/backlog.md`, раздел Next — на файл ТЗ.
- Из записи `agent_docs/development-history/` — на ТЗ, по которому шла итерация.
- Из ТЗ — на ADR с развилками и на PR.

## Архивация

Не архивировать по возрасту: дата в имени файла уже задаёт порядок
(`agent_docs/guides/atomic-documents.md`). ТЗ в статусе «отменено» остаётся на месте —
это решение, а не мусор.
